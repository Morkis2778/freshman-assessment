# 贪吃蛇 V2：最短安全路径搜索

## 打开方法与版本区别

完整解压新版 ZIP，双击根目录 `index.html`，分别进入 V1 与 V2；也可以直接双击 `game/snake_shortest_safe.html`。点击“AI 自动演示”即可自动游戏，选择“快速演示”加速。

| 版本 | 文件 | 决策 |
| --- | --- | --- |
| V1 原版 | `game/snake.html` | 始终沿闭合路线逐格向前，安全但绕路较多 |
| V2 新版 | `game/snake_shortest_safe.html` | A* 搜索安全约束下到食物的最短路线；允许上下左右的捷径，模拟每步身体变化 |

V1 原文件字节未改。V2 使用独立本地存储键，两版主题和战绩互不覆盖。个人网页新增两版入口。

## 为什么不能保证“任何情况下走无约束最短路，同时永久安全”

通向食物的最短路线可能在进食后封住出口，尤其蛇身较长、蛇尾不离开时。最短路径与持续生存并不总能同时成立。只计算 BFS 到食物、吃到后检查能否通向蛇尾，也只是安全启发式，不能据此声称绝对不会死。

V2 明确选择：**在能够证明持续安全的动作集合内寻找最短路线**。它不会声称每次都是完全不受安全约束的全局最短路线。达到搜索预算的个别情况，安全退路也不声称是最短路。界面显示本次规划状态与退路次数。

## 如何搜索

`findSafeShortest` 的节点不是一个蛇头坐标，而是整条蛇的格子列表。代价 g 是步数；启发 h 是蛇头到食物的曼哈顿距离；优先队列按 f=g+h 取最优候选。曼哈顿距离不会高估四邻接移动步数，因此目标节点从队列弹出时，找到的是允许动作集合内的最短路径。

`safeAdvance` 逐步模拟：检查四邻接候选是否在棋盘内；进食时身体增长、尾巴保留，未进食时旧尾格可以释放；检查下一格是否与不能离开的身体重合；再检查路线顺序安全约束。

路径计算完成后缓存下来执行，不会每步重复进行整次搜索。每个缓存动作仍再次检查合法性；吃到食物后清空缓存，对新的食物重新搜索。

## 安全约束并不要求逐格遍历

保留闭合路线只用于给棋盘格子编号，作为证明不会死的工具。设 F(a,b) 是沿该编号正方向从格 a 到格 b 的距离；下一格必须满足：

1. 它是上下左右一个格子的合法移动。
2. 不会撞到本步仍然占用的身体。
3. `0 < F(head,next) <= F(head,tail)`，不越过尾巴的顺序位置。
4. `F(head,next) <= F(head,food)`，不在编号顺序上越过本次食物。

蛇可以横向或纵向直接跨到闭合路线编号相隔很多的位置。这是一次实际移动的“捷径”，不是把路线中间格子逐个走完。例如开局蛇头在 (2,0)，食物在 (2,3)，V2 的测试路径只有向下 3 步；沿 V1 闭合路线到达该格需要 41 步。

初始身体仍按路线顺序排列，每个允许动作都保持这一顺序。蛇未填满棋盘时，闭合路线的下一格始终存在合法安全动作；如果该格恰为旧尾格且未进食，尾格会同步释放。因此不会出现“规划失败后没有合法步可走”。

每一步又严格向食物的编号位置推进，且不跳过食物，所以对每个固定食物最多前进一圈就能到达。这个进展约束同时避免安全追尾策略一直绕圈、永远不吃食物的问题。上述保证只适用于从 AI 按钮创建的初态、当前规则和安全约束，不包括任意手动蛇形的中途接管。

## 搜索预算

A* 每次最多扩展 8000 个状态，避免某些复杂蛇形无限扩大搜索。预算内找到路线，保证该路线是上述约束下的最短路线；预算达到仍未找到，选一个符合相同安全约束且向食物推进的相邻格，然后下一步重新搜索。退路不会破坏安全与最终进食保证，但该次退路没有最短性保证。

## 实际测试

运行 `node tests/test_game_v2_logic.cjs`，直接执行交付 HTML 中的原始 JS。结果保存在 `tests/game_v2_logic_results.json`。测试使用模拟 DOM / Canvas，不代替真实浏览器视觉与触屏验收。

| 指标 | V1 | V2 |
| --- | --- | --- |
| 随机种子测试局数 | 100 | 100 |
| 完成 15 次进食 | 100 / 100 | 100 / 100 |
| 最少步数 | 612 | 112 |
| 最多步数 | 1271 | 229 |
| 平均步数 | 977.43 | 182.88 |

V2 在该测试集的平均步数减少约 81.29%。两版采用相同种子集合，但空格分布会随蛇身变化，所以食物坐标序列并不完全相同；这是随机运行统计比较，不能当作相同食物序列的逐局严格比较。

V2 100 局累计出现 6 次搜索预算退路。额外强制把搜索预算设为 0，仍完成 15 次进食，用 263 步，验证安全退路并不依赖 A* 找到结果。检查了开局无遮挡场景的 3 步最短路径，以及原有碰撞、暂停、进食增长、尾格释放、填满通关、战绩和重置规则。

浏览器运行仍需本人验证：点 AI 自动演示后不输入方向，观察绿色计划路径、本次规划文字、捷径步数与 15 次进食验收结果。原先 `tests/test_game.py` 面向 V1；V2 的自动逻辑测试使用本文件指定的脚本。
