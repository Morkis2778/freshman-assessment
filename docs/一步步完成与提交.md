# 按顺序完成项目与提交

本指南对应随附完整项目。已选小游戏为贪吃蛇，进阶挑战为 PySpice 三个电路；无需再做 2048、扫雷或 Croc。你可以使用 AI，但“个人独立完成”和“讲清楚”需要实际操作、理解与真实记录，不能只把 ZIP 上传当作全部完成。

## 第 1 步：解压与安装工具

将 ZIP **完整解压**到一个普通文件夹；不要在压缩包预览内打开网页。项目目录叫 `freshman-project`。安装 Git、VS Code 和自己选择的 AI 编程工具。AI 工具品牌不限。本项目网页无框架依赖，不需要 npm 或 Node 才能游玩。

建议先用 VS Code 的“文件 → 打开文件夹”打开整个项目；在终端输入 `git --version` 确认 Git 可用。Node 只在可选自动测试中需要；电路仿真使用 Python 与 ngspice。

## 第 2 步：填个人资料

用编辑器修改 `profile.json` 的姓名、专业、年级、兴趣、公开邮箱、简介与目标，不要使用虚构经历。再同步修改 `index.html` 中所有“待填写”位置与仓库链接，以及 LICENSE 的版权姓名。

在安装 Python 依赖后，项目根目录执行：

```bash
python docs/make_profile.py
```

输出新的 `profile.pdf`。打开 PDF 核对字形、姓名、邮箱和换行。网页和 PDF 的信息需要相同。默认 PDF 只是明确标注待填写的模板，不是已经填好你的真实信息。

## 第 3 步：先手动验收贪吃蛇

双击 `index.html`，点击体验贪吃蛇；或者直接双击 `game/snake.html`。

按“手动新一局”，使用方向键 / WASD 或页面按钮。吃食物检查分数增加、身体变长；撞墙检查失败。按空格暂停后等待，蛇不应继续走；再次按空格继续。开启新局，历史最高分和已结束局数不清零。

分别试深浅主题，刷新后检查是否保留。多结束几局，确认只显示最近 10 局。重置按钮会清空最高分、局数和战绩。触屏可滑动或点方向按钮。若浏览器禁用本地存储，应出现提示，游戏本身仍能运行。

把实际结果和测试日期填入 README。当前交付只通过了 Node 逻辑测试，本地浏览器画面与触屏必须你再确认。

## 第 4 步：验收 AI 自动演示

点击“AI 自动演示”，可以选择“快速演示”。点击开始后不操作方向键，等待分数到 15，界面显示“AI 验收通过”。这会自动停下保留结果，便于截图；重新点击可开始新一局。

算法是闭合路线规则控制，不是训练模型。需要能说明：为什么路线覆盖全棋盘、为什么初始身体要按路线摆放、为什么每次向前一格不会撞身、为什么生成在空格的食物最终能吃到。路线安全但不走最短路，这属于明确的设计取舍。

可选自动逻辑验收：安装 Node 后，在项目根目录运行 `node tests/test_game_logic.cjs`。结果写到 `tests/game_logic_results.json`。浏览器端可安装 Playwright 后运行 `python tests/test_game.py`，需要本机允许浏览器进程启动。

## 第 5 步：运行三个电路

Ubuntu / WSL Ubuntu 终端进入项目目录，例如目录在 `~/freshman-project`：

```bash
cd ~/freshman-project
sudo apt update
sudo apt install -y python3 python3-venv python3-pip ngspice libngspice0 libngspice0-dev
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python circuits/rc_filter.py
python circuits/thevenin.py
python circuits/mos_amplifier.py
```

三个程序分别输出数值，并重新生成 `circuits/results/` 的结果；RC 与 MOS 还输出波形和 CSV。查看 `rc_transient.png`、`rc_bode.png`、`mos_waveform.png`。如果报错，保留完整日志再定位，不要删除错误后直接写成功。

主报告采用 `ID=K·Vov²·(1+λVDS)` 的 K 定义，MOS 参考 ID≈0.852713 mA、VDS≈3.294574 V、Av≈−3.30509。如果你的教材采用公式前另有 1/2 的定义，则应使用 README 与脚本中明确列出的另一组结果。向协会确认教材约定后，保持手算、代码和表格一致。

阅读 README 的三个推导，自己从公式算一遍。电路图提供 SVG 与绘图源码；任务书要求自己画图，请在理解连接后自行重绘，或实际修改图纸并记录修改，避免把 AI 绘图直接当作自己的手绘工作。读懂后用自己的话改写 README 第 5 节，并补齐本人复现信息。

## 第 6 步：建立 GitHub 仓库与两步验证

注册 / 登录自己的 GitHub。创建一个公开仓库，建议取名 `freshman-assessment`。若使用下方 Git 推送方式，建立**空仓库**，暂不勾选自动创建 README、LICENSE 或 .gitignore，以免产生额外初始提交需要合并。

到账号 Settings → Password and authentication，根据官方流程开启两步验证。恢复码保存在自己的安全位置，勿写进 README，勿上传仓库。完成后才能把 README 中状态改成已开启。

项目内保留实际的 AI 构建 Git 提交，作者是 AI Project Builder，不能冒称为自己的历史。解压工具需保留 `.git`。用 `git log --oneline` 检查；你实际改完个人资料、规则解释和复现记录后，再追加真实本人提交。提交次数是工作记录，不是随意改几个空格凑数。

在项目目录配置**自己的**提交身份：

```bash
git config user.name "你的真实姓名或 GitHub 昵称"
git config user.email "你的 GitHub 邮箱或隐私邮箱"
git status
```

根据实际修改分别提交；下面仅示例，文件确有修改才执行：

```bash
git add index.html profile.json profile.pdf LICENSE
git commit -m "docs: fill my real profile"
git add README.md
git commit -m "docs: explain logic after local reproduction"
```

如果 `.git` 因解压设置丢失，不要伪造历史。先 `git init -b main`，在真实操作过程中逐阶段提交个人页面、游戏修改、电路实验及文档，保持至少三次真实提交。

## 第 7 步：上传全部文件

把下面 URL 的用户名和仓库名替换成你的实际值。不要把示例原样复制后当成真实地址：

```bash
git remote add origin https://github.com/你的用户名/freshman-assessment.git
git push -u origin main
```

如果提示 origin 已存在，用 `git remote -v` 核查现有 URL。推送认证按 GitHub 客户端 / Git Credential Manager 引导完成；不要把账号密码或令牌写进代码。也可以使用 GitHub Desktop 加入现有本地仓库并发布，以保留提交历史。仅网页批量上传通常不会保留现有本地提交历史。

确认仓库根目录直接有 `index.html`、`README.md`、`profile.pdf`、`game/` 和 `circuits/`，不要多套一层 `freshman-project/`，否则 Pages 根目录可能找不到主页。

## 第 8 步：部署 GitHub Pages

仓库 Settings → Pages → Build and deployment：Source 选择 `Deploy from a branch`，Branch 选择 `main`，目录选择 `/ (root)`，保存。根目录已经有 `.nojekyll`，静态页面不需要框架构建。

部署完成后，按 GitHub 显示的实际地址打开，通常是 `https://你的用户名.github.io/freshman-assessment/`。检查：主页正常、游戏正常、PDF 能打开、图片正常。不要只验证本地路径。

将真实网址和仓库链接填入 README 与主页，提交再推送。若暂时 404，查看 Pages 的部署状态与 Actions 日志，检查是否选错分支、目录或根目录缺 `index.html`。本项目没有代你上线。

## 第 9 步：最后提交前核查

逐项勾选 README 的验收清单：真实个人信息、本人图纸与计算、浏览器两阶段游戏演示、PySpice 三个实验、至少三次真实提交、MIT 与字体许可、本人代码解释、真实提示词与迭代、本人 AI 错误查证、两步验证、真实 Pages 网址。

最后将**仓库链接**发到任务书指定的群内收集表，按实际截止时间提交。公开前只保留适合公开的联系方式。
